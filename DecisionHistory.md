## DC-2026-08-04-BUG-INTAKE-01 — Coordinator failures use an independent open-bug channel

ID: DC-2026-08-04-BUG-INTAKE-01 · Details: [supporting record](DecisionDetails/DC-2026-08-04-BUG-INTAKE-01.md)

Decision: Store only currently open Coordinator bug reports as bounded atomic JSON records in one shared local filesystem registry that remains usable without repository enrollment, profiles, authority, broker, API, testd, or the call journal. Identical local failures coalesce; closing physically removes the record, and a later recurrence creates a new bug identity. Agents must include expected behavior, actual behavior, cross-server reproducible steps, and available correlation identities. The Console exports and imports self-contained JSON bundles; imported reports retain a visible remote origin and never merge with a local observation. After reporting a test-harness failure, agents may continue repository-native isolated tests only as clearly labeled local advisory evidence; those results never enter Coordinator statistics or satisfy governed handoff/release evidence, and shared runtime work still requires Coordinator ownership.

Why: Broker/database-backed intake, automatic cross-server replication, the ordinary call journal, durable closed histories, stopping all testing, and silently bypassing the harness were considered. Broker and journal paths can fail with the component being diagnosed; automatic replication adds a permanently connected coordination service that is unavailable in the stated environment; closed histories add synchronization and retention machinery the user rejected; stopping tests blocks development; silent bypass makes evidence misleading. An open-only shared directory plus inspectable copy/paste bundles gives each server a failure-independent path, while explicit origin and advisory fallback preserve truthful provenance and coding throughput.

## DC-2026-08-04-FIRST-USE-TRUST-01 — First use executes as the actual local caller

ID: DC-2026-08-04-FIRST-USE-TRUST-01 · Details: [supporting record](DecisionDetails/DC-2026-08-04-FIRST-USE-TRUST-01.md)

Decision: During a valid typed first-use repository adoption, atomically create or refresh routing/execution state for the actual non-root local caller and durably record that UID as both execution identity and attribution. Filesystem stat owner, root, and control-plane accounts never select or substitute for repository execution. On a fresh launch, only after exact-port preflight, descriptor-walk the exact validated working directory, prune `.git`, do not follow symlinks, skip multiply linked regular files, and restore only group-class `rwX`/POSIX-ACL-mask bits while preserving bytes, UID/GID, named ACL entries, world bits, and executable intent. Give the root authority a writable `/home` sandbox view for this code-bounded operation instead of installer-maintained per-home exceptions; repository code never inherits it. Do not set `UMask=0000`, broadly normalize the source root, or grant repository code privilege. Keep repository identity/generation, path containment, TTL, idempotency, cleanup, and explicitly disabled action/lifecycle state. This supersedes the peer-UID/ACL local-authorization and filesystem-owner execution-selection portions of DC-2026-07-15-HOST-01; public identity and secret boundaries remain unchanged. Future deployments of this confirmed behavior are ordinary implementation, not a new security decision.

Why: Manual per-account enrollment and repair, per-home write exceptions, filesystem-owner execution, root/control-plane execution, broad world/mode normalization, and no durable execution record were considered. The first three recreated multi-tenant friction, failed for newly encountered accounts, or chose an identity unrelated to caller intent; privileged execution widened repository authority; broad normalization changed unrelated metadata; no record lost accounting and cleanup. Actual-caller execution plus one narrowly bounded ACL-mask repair matches the confirmed single-developer host while retaining exact lifecycle controls and attribution.

Independent supervision, exact profile identity reload, and exact convergence preserve intentional maintenance control without hiding partial startup, rollback, or migration failure.

## DC-2026-07-15-HOST-01 — One attributed authority owns each managed host

ID: DC-2026-07-15-HOST-01 · Details: [supporting record](DecisionDetails/DC-2026-07-15-HOST-01.md)

Decision: Use one service-owned database and kernel-attributed broker socket as the authority for all local accounts and agents on a host; clients never open that database.
