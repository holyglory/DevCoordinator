| ID | Applies to | Mistake pattern | Required behavior | Prevention and verification |

| UIL-DOCUMENTATION-001 | Coordinator skill runtime guidance | The skill said host-visible servers must use Coordinator but did not explain the supported first-use journey for a new repository or distinguish an existing target lifecycle action from a new bounded development service, so agents tried a sandbox bind and then reached an undocumented enrollment dead end. | The canonical skill gives one copyable decision path: ordinary source work needs no Coordinator; an existing enrolled target uses status/start/stop/restart; a new repository development server uses non-mutating discovery followed by one structured TTL-owned dev-service start. It explains that sandbox `EACCES`/`EPERM` bind failures mean Coordinator was not invoked, that “local fallback disabled” is not a recovery instruction, exact-port behavior, required argv/cwd/TTL/cleanup inputs, contact/mutation truth, and how to follow an uncertain operation. | Static skill checks require the new-repository and dev-server journey, direct-bind and local-fallback diagnosis, examples, field meanings and exact failure recovery. Source-level negative tests require malformed serve calls and unenrolled lookups to return truthful broker-contact/mutation fields and a copyable help/follow command. Software-owned acceptance executes the documented command shape from a zero-commit repository and verifies it produces a fetchable attributed server plus TTL cleanup. |
| UIL-DOCUMENTATION-002 | Coordinator failure reporting and test fallback | Agents were told not to bypass the Coordinator but were not given an outage-safe bug-report command or a precise way to keep coding when only the governed test harness failed, so development could block and failures reached the Coordinator team as incomplete prose. | The canonical skill provides a copyable structured bug-report workflow that works without broker/profile/repository discovery, requires expected behavior, actual typed failure, reproducible steps and available correlation IDs, and explains how to close or inspect an open report. If the test harness is unavailable, agents may run repository-native isolated tests directly to keep coding, but must label them local/advisory, never publish them as Coordinator/release evidence, and must not use the fallback to mutate shared host runtimes, containers, listeners or databases. | Static skill checks require the report command, mandatory reproduction fields, local-test fallback boundary, evidence label and shared-runtime prohibition. A fresh-agent forward test must choose bug reporting plus advisory native tests for a simulated harness outage, while refusing to claim governed evidence or bypass runtime ownership. |
