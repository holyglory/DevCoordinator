# User Issue Ledger: UI

| ID | Applies to | Mistake pattern | Required behavior | Prevention and verification |
| --- | --- | --- | --- | --- |
| UIL-UI-001 | Responsive Console detail panels and disclosure content | A narrow detail drawer retained a wide evidence grid and rendered absent optional nodes as visible `null` text. | Detail panels keep all available information readable at their rendered width, with no horizontal clipping or synthetic placeholder text. | Use width-aware component rules, filter optional DOM nodes before `replaceChildren`, and exercise an expanded populated Run detail at desktop-drawer and mobile widths in browser verification. |
| UIL-UI-002 | Tests fleet and repository heatmaps | Per-hour failure and infrastructure warning symbols made an intensity heatmap read as a failure dashboard, even though ordinary development includes failing tests. | Heatmap cells encode aggregate test time only. Exact test, failure and infrastructure counts remain available on hover, focus and touch, and in repository detail. | Do not attach warning classes or icons to heatmap cells. Verify populated failure/infrastructure fixtures render cells with no alert icon or alert styling, while the exact-value popup exposes all counts at desktop and mobile widths. |
| UIL-UI-003 | Console project usage history | A root repository displayed live CPU/memory but its history control queried a different metric identity from the one the sampler recorded, leaving a permanent “No history yet” state. | Every visible usage-history control resolves the same immutable series key that the metrics store publishes, or truthfully has no telemetry. | Test authoritative repository-tree ingestion for root and family keys, then exercise the Projects usage popover with populated history in browser verification. |
| UIL-UI-004 | Tests fleet attention and repository health | A rolling-window infrastructure incident remained labeled as a current “Needs attention” condition after the repository had demonstrably recovered. Treating any later successful target as recovery would also be misleading because another target can remain infrastructure-failed. | Current attention contains only unresolved conditions. Historical infrastructure counts and hourly evidence remain discoverable, but only a strictly later terminal run whose entire run succeeded, has measured attempt evidence, and contains no infrastructure-failed attempt resolves earlier infrastructure incidents for the repository. | Produce terminal runs in both orders and prove only a fully successful measured run strictly after the latest infrastructure-bearing run clears current attention. Unmeasured success, partial target success, a clean success before a later incident, and test failures must not clear it. Verify the recovered repository remains healthy while its summary and hourly history retain the incident count. |
| UIL-UI-005 | Console performance accounting and project detail | Whole-host memory (`MemTotal - MemAvailable`) was shown beside a partial sum of project RSS and container working sets without a reconciled residual, common sample boundary, or compatible labels, so tens of GiB appeared to be missing; later revisions hid the residual behind a vague catch-all or warning banner, then treated inclusive `devcoordinator.slice`, developer sessions, repository sums, and browser rows as if overlapping clues could be added together; repeating a full chart for every project, similar colors, and a disconnected legend made the discrepancy harder to inspect. A later legend implementation mapped every repository to the same Project runtimes bars and Agent browsers to the much larger Developer-account sessions bars, so hover claimed unrelated aggregate geometry represented the selected drilldown—even for a 0 B repository. | Performance presents one dense whole-server composition whose additive stack contains only disjoint cgroup roots for project runtimes, Coordinator control, Coordinator background/scheduler, active test attempts, and developer-account sessions, followed by estimated system/unclassified memory and available memory. Repository totals, Agent browsers, child cgroups, `system.slice`, and host counters are explicitly non-additive drilldowns; the inclusive Coordinator parent is never sampled into the stack. Cgroup working memory, anonymous, shared, kernel, CPU, process, and active-child observations are labelled by their real basis; unavailable PSS is never inferred. Repository and measured-category colors are distinct. Legend hover/focus on an additive category emphasizes its exact stack segment; hover/focus on a non-additive repository or Agent-browser row renders only that row's exact observed-value history as a visibly non-additive overlay on the same host scale. A drilldown never borrows its parent bars, a 0/0 series does not dim or highlight the chart, and project/browser details open on demand in the stable accessible modal. | Feed schema-2 disjoint roots plus conflicting repository/browser/system diagnostics and prove stack values reconcile exactly once to host used/capacity, repository and browser stack contribution is zero, the inclusive Coordinator parent is absent, and an attribution gap remains visible rather than reassigned. Verify bounded account/test child drilldowns, truthful cgroup-counter/PSS copy, unique colors, exact-key hover/focus overlays whose geometry matches retained `observedValue`/host-total ratios, distinct repository selections, a current-zero/historical-peak Agent-browser series, a 0/0 repository with no false chart emphasis, dialog behavior, refresh persistence, and no clipping or document-width overflow at 320, 390, 768, 981, and 1440 px. |
| UIL-UI-006 | Projects repository and resource rows | Root repository rows exposed an internal `ROOT` hierarchy badge that conveyed no actionable distinction on a root-repository collection, while optional visibility controls and responsive child-row facts consumed different widths and shifted equivalent lifecycle buttons and icons away from common columns. | A Projects row leads with the repository or resource name and omits redundant internal hierarchy labels. Project headers and every child resource row use explicit, stable identity, telemetry, state, and action tracks at each supported layout. Every equivalent row reserves the same action geometry, including a stable visibility-control slot, so equivalent lifecycle buttons and icons align whether or not optional content is present. The optional control retains an accessible name and does not become a visible placeholder. | Render populated project and child rows with short/long names, running/stopped state, telemetry present/absent, and visibility control present/absent at 1135, 763, 390, and 320 px. Assert no visible root-kind badge or `ROOT` text, equivalent controls share track positions within rendering tolerance, stable slots do not collapse, only actionable controls are keyboard/focus exposed, and neither the section nor document overflows horizontally. |
| UIL-UI-007 | Projects resource-kind indicators | Repeated uppercase text pills such as `CONTAINER` consumed the first column of every child row without helping scanning, while a bare replacement icon would be ambiguous to pointer, keyboard, and touch users. | Use the Console's established icon language for resource kinds. Each compact icon has a programmatic accessible name and an on-demand hint that spells out the resource type and its meaning on hover, keyboard focus, and touch/click; normal rows do not repeat the full type as a permanent badge. Hints remain viewport-bounded, do not alter row geometry, and close without stealing row actions. | Exercise every rendered resource kind with pointer, keyboard, and touch activation at wide and narrow widths. Assert the text pill is absent, icons are distinct and aligned, accessible names remain available, exact hint text appears on demand and dismisses, focus returns predictably, and no tooltip/hint is clipped, overlapping an action, or causing document overflow. |
| UIL-UI-008 | Resource-local Console failures | Opening one server or container log disclosure could render its useful inline error and also raise the same resource-local failure as a persistent global banner, making one unavailable log look like a Console-wide incident and displacing every page. A details row with no authoritative service log source later still advertised logs, performed a doomed request, and made every Servers production viewport fail. | A resource-local log load failure remains inside the exact expanded log panel with a useful retry action; it never raises a global banner, clears healthy inventory, collapses the disclosure, or loses the user's focus and scroll context. A server without an authoritative log source keeps its useful details but exposes no log Refresh affordance and performs no log request. Authentication expiry may still enter the shared authentication flow, and genuine control-plane-wide failures retain their global treatment. | Return typed 4xx, 5xx, and transport failures for exact server and container log reads at wide and narrow widths. Assert the panel stays open with its inline error and working refresh, no global banner appears, healthy surrounding content remains stable, focus/scroll are preserved, and a later successful refresh replaces only that panel's error with logs. Render a server without a log source and prove details work while no log-capable marker, Refresh control, loading/error state, or API call exists. Production acceptance must search across collapsed groups for a genuinely log-capable resource and fail—not merely mark the journey exercised—when that opened panel contains its error state. |
| UIL-UI-009 | Open Coordinator bugs | Coordinator defects had no durable Console destination, while retaining closed reports would turn a small actionable list into synchronization history and make multiple instances disagree. | Bugs is an authenticated open-only collection whose current reports are the first substantial content. Its badge is hidden at zero. Each row explains component, summary, occurrence/freshness, expected versus actual behavior, reproducible steps and correlation handles; closing names the exact report and removes it immediately. Closed reports, internal filesystem paths and malformed records never appear as normal content. Background refresh retains rows, disclosures, focus and scroll, and a Coordinator outage cannot clear or disable the page. | Exercise empty, populated, duplicate, malformed, close-success, close-race and store-unavailable states through two Console instances. Verify an owner can close an exact report, a non-owner cannot, the physical file and both views lose it, zero hides the nav badge, retained rows do not blink, and desktop/mobile layouts have no clipping or document overflow from 320 px upward. |
| UIL-UI-010 | Portable open-bug transfer | Open bugs on one Coordinator server could not be moved to another, and a copied report could be mistaken for a locally observed failure or depend on a repository path that does not exist on the receiving server. | Bugs provides Export and Import actions beside the collection. Export opens a dialog containing a complete bounded JSON bundle and a Copy to Clipboard action while leaving the text selectable for manual copy. Import opens a large paste field, validates the complete bundle, and atomically adds idempotent open reports. Every report carries a stable origin-server identity; imported reports are visibly labelled remote and preserve their original bug identity across re-export, while local reports remain labelled this server. Transfer data contains portable, redacted reproduction steps, structured command arguments, repository name and correlations, never a private server path or an assumption that the source repository exists locally. | Export local and already-imported reports, import the bundle twice into another server, and prove stable origin, idempotency, no local/remote dedupe collision, no private paths/secrets, and no partial writes on one invalid record. Exercise successful clipboard copy and forced clipboard failure with manual text selection, invalid/oversized JSON, owner-only import, close of an imported report, multi-instance convergence, keyboard focus, and 320 px geometry. |
