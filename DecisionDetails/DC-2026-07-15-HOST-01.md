# DC-2026-07-15-HOST-01 — One peer-authenticated authority owns each managed host

## Durable decision

The service-owned database and peer-authenticated broker socket are the single
default authority for every enrolled OS account and agent on a managed host.
Clients never open or merge that database. Per-user journals and files are
non-authoritative launch, log, migration, and recovery evidence; explicit
account mode is isolated compatibility or test scope, never host-global proof.

The broker authorizes each request from peer UID, protected enrollment profile,
exact repository/resource membership, and the current action grant. Repository
and privileged Compose paths are opened and proved by descriptor-anchored type,
owner, mode, symlink, and native ACL checks. Non-owner mutation-capable ACLs are
rejected; unsupported rich ACL models fail closed. Host observation receives
only the capability it needs, and ambient/inheritable capabilities are cleared
before managed children execute.

Authorization schema changes provide an offline exact migration from protected
profiles into the service database. Profile/database drift is rejected before
restart; a narrowly proved generation-forward reconciliation may change only
the expected scalar while preserving UID, repository identity, active
installation, ACL digest, and grants. Account-home paths are explicit and based
on the effective login account rather than a remapped `HOME` or manager-context
home expansion.

## Alternatives rejected

Per-account writable authorities produced conflicting inventories, leases, and
project ownership. Cross-user writable SQLite and UI-side merging weaken
authentication and retain multiple writers. Mode-bit checks miss extended
grants, text parsing reintroduces locale and path races, broad root execution or
writable home mounts exceed the mutation scope, and silently accepting an ACL
model the broker cannot evaluate breaks the proof boundary.

## Verification contract

Broker enrollment, profile-link, host, filesystem-ACL, repository-context, and
server-wide installation tests cover cross-UID grants, revocation, drift,
unsupported authority, remapped homes, and exact migration. Production restart
remains gated on two-way profile/database consistency and the exact readiness
graph.
