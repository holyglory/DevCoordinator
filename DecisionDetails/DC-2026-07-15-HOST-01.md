# DC-2026-07-15-HOST-01 — One attributed authority owns each managed host

## Durable decision

The service-owned database and kernel-attributed broker socket are the single
default authority for every local account and agent on a managed host. Clients
never open or merge that database. Per-user journals, profiles, and files are
non-authoritative routing, attribution, launch, log, migration, and recovery
evidence; explicit account mode is isolated compatibility or test scope, never
host-global proof.

On the confirmed single-developer host, peer UID, UID/GID, filesystem owner,
mode, POSIX ACL, group membership, socket metadata, link count, and writable
ancestors do not authorize a local request. The broker records peer UID for
attribution and execution routing, then validates typed message shape, exact
repository/resource identity and generation, path containment, idempotent
operation identity, and explicit action/lifecycle state. A first-use repository
command runs only as its actual non-root local caller; filesystem stat owner,
root, and control-plane accounts never substitute for that execution identity.

Profiles and database records may route requests and preserve disabled state,
but a missing local-account record is provisioned by the valid typed first-use
flow rather than treated as a tenant authorization failure. Explicitly disabled
Coordinator actions, enrollments, repositories, and lifecycle states remain
disabled. Profile/database drift that changes exact repository identity,
generation, action, or lifecycle meaning remains a consistency failure.

Public Google login, Console/domain grants, Telegram ownership, external
upstreams, and secret-bearing credential transports remain security boundaries.
Protected host services receive only the OS capabilities they need, and
ambient/inheritable capabilities are cleared before managed children execute.

The local-account authorization, native-ACL authorization, and filesystem-owner
execution-selection parts of the original decision are superseded by
[DC-2026-08-04-FIRST-USE-TRUST-01](DC-2026-08-04-FIRST-USE-TRUST-01.md). The
single authority and exact identity/lifecycle portions remain current.

## Alternatives rejected

Per-account writable authorities produced conflicting inventories, leases, and
project ownership. UI-side merging and multiple writable SQLite authorities
retain multiple writers and cannot arbitrate host lifecycle. Manual enrollment,
UID/owner/mode/ACL authorization, and filesystem-owner execution were rejected
because they recreated a multi-tenant threat model, blocked valid cross-account
work, and selected an execution identity unrelated to the caller. Broad root
execution and writable whole-home mounts were rejected because the actual
non-root caller supplies sufficient attribution and execution scope.

## Verification contract

Broker, repository-context, and server-wide installation tests must prove that
cross-UID calls are not denied or rerouted by filesystem metadata, the actual
non-root caller is durably attributed and executes repository code, and root or
control-plane identities never do. Negative tests retain exact identity,
generation, path, operation, and explicitly disabled action/lifecycle failures.
Public identity and secret tests remain separate and fail closed. Production
restart remains gated on semantic profile/database consistency and the exact
readiness graph, never on local-account permission metadata.
