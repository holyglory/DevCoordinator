# DC-2026-07-11-20 — DevCoordinator owns its source and publication gate

## Durable decision

DevCoordinator is the independent canonical repository for the Coordinator and
PostgreSQL protection skills, DevOps Board, DevOps Console, deployment assets,
and their validation. It has no dependency on holyskills. Agent-facing skills
remain runtime-neutral for Codex and Claude Code, and installed copies are
verified direct links managed transactionally from this writable source rather
than edited or copied forks.

Before a broad audit, refactor, migration, split, or history change, fetch the
remote default and classify ancestry. Preserve valuable dirty work and
reconcile a stale base semantically; never reset or overwrite either history to
manufacture cleanliness. Before publication, validate a fresh clone of the
exact commit, copied standalone skills in normal and optimized Python,
repository boundaries, generated/package provenance, and public-artifact
hygiene.

Interface evidence comes from production views with source-bound renderer
inputs and realistic detector recall/false-positive controls. DevOps Board
build, test, snapshot, package, launch, debug, and automation use the Build
macOS Apps workflow so native source, signing, package, and launched binary
identity remain attributable.

## Alternatives rejected

Keeping operations tooling embedded in a broader skills repository blurred
ownership and release responsibility. Copied skill installs drift. In-place
validation can borrow ignored files, generated leftovers, or local links. A
stale-base push can discard remote work, while a reset can discard local work.
Ad-hoc native commands bypass the delivery evidence required for the actual
application.

## Verification contract

`scripts/check_repository_freshness.py`,
`scripts/check_repository_boundaries.py`, `scripts/public_artifact_guard.py`,
and `scripts/validate.py` enforce source and publication boundaries. Native
readiness additionally requires the Build macOS Apps-owned gate; skipped live
package journeys remain visible in `CompletionLedger.md`.
